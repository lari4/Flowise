Документация всех возможных пайплайнов работы агентов в Flowise - как промты объединяются, какие данные передаются между шагами, и как строятся сложные AI-системы.

1. [ConversationalRetrievalQA Pipeline](#1-conversationalretrievalqa-pipeline) - Диалоговая система с поиском по документам

3. [ConversationalAgent Pipeline](#3-conversationalagent-pipeline) - Разговорный агент с инструментами
4. [XMLAgent Pipeline](#4-xmlagent-pipeline) - Агент с XML-структурированным выводом
5. [MultiAgent Supervisor Pipeline](#5-multiagent-supervisor-pipeline) - Координация нескольких агентов
6. [Retriever Pipelines](#6-retriever-pipelines) - Различные стратегии поиска информации

## 1. ConversationalRetrievalQA Pipeline

**Назначение:** Диалоговая система для ответов на вопросы по документам с сохранением контекста беседы.

**Файл:** `packages/components/nodes/chains/ConversationalRetrievalQAChain/`

### Схема работы

```
┌─────────────────────────────────────────────────────────────────┐
│                    ВХОДНЫЕ ДАННЫЕ                                │
├─────────────────────────────────────────────────────────────────┤
│ • User Question (текущий вопрос)                                 │
│ • Chat History (история диалога)                                 │
│ • Vector Store (векторная база с документами)                    │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│           ШАГ 1: ПЕРЕФОРМУЛИРОВАНИЕ ВОПРОСА                      │
├─────────────────────────────────────────────────────────────────┤
│ Промт: CUSTOM_QUESTION_GENERATOR_CHAIN_PROMPT                   │
│                                                                  │
│ Входные переменные:                                              │
│   {chat_history} ← История предыдущих сообщений                 │
│   {question} ← Текущий вопрос пользователя                      │
│                                                                  │
│ Процесс:                                                         │
│   LLM анализирует вопрос в контексте истории и создаёт          │
│   standalone вопрос, понятный без контекста                     │
│                                                                  │
│ Выходные данные:                                                 │
│   standalone_question = "Переформулированный вопрос"            │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│              ШАГ 2: ПОИСК РЕЛЕВАНТНЫХ ДОКУМЕНТОВ                │
├─────────────────────────────────────────────────────────────────┤
│ Компонент: Vector Store Retriever                               │
│                                                                  │
│ Входные данные:                                                  │
│   standalone_question (из Шага 1)                               │
│                                                                  │
│ Процесс:                                                         │
│   1. Создание эмбеддинга standalone_question                    │
│   2. Similarity search в векторной БД                           │
│   3. Возврат топ-K наиболее релевантных документов              │
│                                                                  │
│ Выходные данные:                                                 │
│   relevant_docs = [Document1, Document2, ..., DocumentK]        │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│          ШАГ 3: ФОРМИРОВАНИЕ КОНТЕКСТА                          │
├─────────────────────────────────────────────────────────────────┤
│ Процесс:                                                         │
│   Объединение текстов из relevant_docs в единую строку          │
│                                                                  │
│ Выходные данные:                                                 │
│   context = "Document1.text\n\nDocument2.text\n\n..."           │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│           ШАГ 4: ГЕНЕРАЦИЯ ОТВЕТА                               │
├─────────────────────────────────────────────────────────────────┤
│ Промт: RESPONSE_TEMPLATE или QA_TEMPLATE                        │
│                                                                  │
│ Входные переменные:                                              │
│   {context} ← Контекст из релевантных документов (Шаг 3)       │
│   {question} ← Оригинальный вопрос пользователя                 │
│                                                                  │
│ Процесс:                                                         │
│   LLM анализирует контекст и генерирует ответ на вопрос.        │
│   Если в контексте нет релевантной информации →                 │
│   "Hmm, I'm not sure"                                           │
│                                                                  │
│ Выходные данные:                                                 │
│   answer = "Ответ на основе предоставленных документов"         │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│           ШАГ 5: ОБНОВЛЕНИЕ ИСТОРИИ                             │
├─────────────────────────────────────────────────────────────────┤
│ Процесс:                                                         │
│   chat_history.append({                                         │
│     human: original_question,                                   │
│     ai: answer                                                  │
│   })                                                            │
│                                                                  │
│ Выходные данные:                                                 │
│   Обновлённая chat_history для следующего вопроса               │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
                      ┌───────────────┐
                      │ ФИНАЛЬНЫЙ     │
                      │ ОТВЕТ         │
                      │ ПОЛЬЗОВАТЕЛЮ  │
                      └───────────────┘
```

### Передача данных между промтами

1. **User Question + Chat History** → **CUSTOM_QUESTION_GENERATOR_CHAIN_PROMPT**
   - Преобразование: Follow-up вопрос → Standalone вопрос

2. **Standalone Question** → **Vector Store Retriever**
   - Преобразование: Текст → Эмбеддинг → Релевантные документы

3. **Retrieved Documents** → **Context Aggregation**
   - Преобразование: Массив документов → Единая строка контекста

4. **Context + Original Question** → **RESPONSE_TEMPLATE**
   - Преобразование: Контекст + Вопрос → Финальный ответ

### Ключевые особенности

- **Сохранение контекста:** История диалога используется для понимания follow-up вопросов
- **Изоляция поиска:** Поиск выполняется по standalone вопросу, независимо от истории
- **Защита от галлюцинаций:** Явное указание отвечать только на основе контекста
- **Масштабируемость:** Работает с большими документами через векторный поиск

## 2. BabyAGI Pipeline

**Назначение:** Автономный агент с самоуправляемой системой задач. Создаёт, приоритизирует и выполняет задачи для достижения заданной цели.

**Файл:** `packages/components/nodes/agents/BabyAGI/core.ts`

### Схема работы

```
┌─────────────────────────────────────────────────────────────────┐
│                    ВХОДНЫЕ ДАННЫЕ                                │
├─────────────────────────────────────────────────────────────────┤
│ • Objective (главная цель)                                       │
│ • First Task (первая задача)                                     │
│ • Max Iterations (максимальное количество итераций)              │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
                   ┌──────────────────┐
                   │ ИНИЦИАЛИЗАЦИЯ    │
                   ├──────────────────┤
                   │ task_queue = []  │
                   │ task_queue.add({ │
                   │   id: 1,         │
                   │   task: first    │
                   │ })               │
                   └──────────────────┘
                              │
                   ┌──────────▼───────────┐
                   │   ОСНОВНОЙ ЦИКЛ      │
                   │ (пока queue не пуст) │
                   └──────────┬───────────┘
                              │
┌─────────────────────────────┼─────────────────────────────┐
│                             │                             │
│          ИТЕРАЦИЯ ЦИКЛА (повторяется до макс. итераций)   │
│                             │                             │
└─────────────────────────────┼─────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│           ШАГ 1: ВЫПОЛНЕНИЕ ЗАДАЧИ                              │
├─────────────────────────────────────────────────────────────────┤
│ Промт: BABYAGI_EXECUTION_PROMPT                                 │
│                                                                  │
│ Входные переменные:                                              │
│   {objective} ← Главная цель системы                            │
│   {context} ← Результаты ранее выполненных задач                │
│   {task} ← Текущая задача для выполнения                        │
│                                                                  │
│ Процесс:                                                         │
│   1. Получить первую задачу из очереди                          │
│   2. Найти релевантный контекст из ранее выполненных задач      │
│      (используя векторный поиск по схожести)                    │
│   3. LLM выполняет задачу с учётом objective и context          │
│                                                                  │
│ Выходные данные:                                                 │
│   task_result = "Результат выполнения задачи"                   │
│   completed_tasks.append({                                      │
│     task: current_task,                                         │
│     result: task_result                                         │
│   })                                                            │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│           ШАГ 2: СОЗДАНИЕ НОВЫХ ЗАДАЧ                           │
├─────────────────────────────────────────────────────────────────┤
│ Промт: BABYAGI_TASK_CREATION_PROMPT                             │
│                                                                  │
│ Входные переменные:                                              │
│   {objective} ← Главная цель системы                            │
│   {result} ← Результат только что выполненной задачи (Шаг 1)   │
│   {task_description} ← Описание выполненной задачи              │
│   {incomplete_tasks} ← Список оставшихся задач в очереди        │
│                                                                  │
│ Процесс:                                                         │
│   LLM анализирует результат и создаёт новые задачи,             │
│   которые помогут достичь objective и не дублируют              │
│   существующие задачи                                           │
│                                                                  │
│ Выходные данные:                                                 │
│   new_tasks = [                                                 │
│     "Новая задача 1",                                           │
│     "Новая задача 2",                                           │
│     ...                                                         │
│   ]                                                             │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│           ШАГ 3: ПРИОРИТИЗАЦИЯ ЗАДАЧ                            │
├─────────────────────────────────────────────────────────────────┤
│ Промт: BABYAGI_TASK_PRIORITIZATION_PROMPT                       │
│                                                                  │
│ Входные переменные:                                              │
│   {task_names} ← Все задачи (старые + новые из Шага 2)         │
│   {objective} ← Главная цель команды                            │
│   {next_task_id} ← ID для начала нумерации                      │
│                                                                  │
│ Процесс:                                                         │
│   1. Объединить incomplete_tasks + new_tasks                    │
│   2. LLM переупорядочивает задачи по важности                   │
│   3. Назначает приоритеты с учётом objective                    │
│                                                                  │
│ Выходные данные:                                                 │
│   prioritized_tasks = [                                         │
│     {id: 2, task: "Самая важная задача"},                       │
│     {id: 3, task: "Вторая по важности"},                        │
│     ...                                                         │
│   ]                                                             │
│                                                                  │
│ Обновление очереди:                                              │
│   task_queue = prioritized_tasks                                │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
                   ┌──────────────────┐
                   │ ПРОВЕРКА УСЛОВИЙ │
                   ├──────────────────┤
                   │ Очередь пуста?   │
                   │ ИЛИ              │
                   │ Max iterations?  │
                   └────┬─────────┬───┘
                        │         │
                   Нет  │         │ Да
                        │         │
                        │         ▼
                        │   ┌──────────┐
                        │   │  ВЫХОД   │
                        │   │  ЗАВЕР-  │
                        │   │  ШЕНИЕ   │
                        │   └──────────┘
                        │
                        └──► Возврат к Шагу 1 (следующая итерация)
```

### Передача данных между промтами

**Циклический поток данных:**

```
EXECUTION → result → TASK_CREATION → new_tasks ──┐
    ▲                                             │
    │                                             ▼
    │                              PRIORITIZATION (объединение)
    │                                             │
    │                                             ▼
    └───────────────── prioritized_tasks ─────────┘
```

1. **Objective + Context + Task** → **EXECUTION_PROMPT**
   - Преобразование: Задача → Результат выполнения

2. **Result + Task Description + Incomplete Tasks** → **TASK_CREATION_PROMPT**
   - Преобразование: Результат → Массив новых задач

3. **All Tasks + Objective** → **PRIORITIZATION_PROMPT**
   - Преобразование: Неупорядоченный список → Приоритизированная очередь

4. **Приоритизированная очередь** → Возврат к **Шагу 1**
   - Цикл продолжается с новой первой задачей

### Использование векторной памяти

```
┌──────────────────────────────────────┐
│     ВЕКТОРНАЯ ПАМЯТЬ (опционально)   │
├──────────────────────────────────────┤
│                                      │
│ При выполнении задачи (Шаг 1):       │
│   1. completed_tasks → embeddings    │
│   2. Similarity search для context   │
│   3. Топ-K релевантных результатов   │
│      передаются в EXECUTION_PROMPT   │
│                                      │
│ Эффект:                              │
│   Агент "помнит" релевантные         │
│   результаты прошлых задач           │
└──────────────────────────────────────┘
```

### Ключевые особенности

- **Автономность:** Агент сам создаёт и управляет задачами
- **Адаптивность:** Новые задачи создаются на основе результатов
- **Приоритизация:** Задачи постоянно переупорядочиваются по важности
- **Долговременная память:** Векторное хранилище для доступа к прошлым результатам
- **Целеориентированность:** Все действия направлены на достижение objective

### Пример потока данных

```
Objective: "Написать отчёт о рынке AI"
First Task: "Исследовать текущие тренды в AI"

Итерация 1:
  Execution: "Основные тренды: LLM, computer vision, robotics"
  ↓
  Task Creation: ["Проанализировать рынок LLM",
                  "Изучить применение computer vision",
                  "Исследовать robotics startups"]
  ↓
  Prioritization: [1. "Проанализировать рынок LLM",
                   2. "Изучить применение computer vision",
                   3. "Исследовать robotics startups"]

Итерация 2:
  Execution: "Рынок LLM: OpenAI, Anthropic, Google..."
  ↓
  Task Creation: ["Сравнить модели GPT и Claude",
                  "Оценить размер рынка LLM"]
  ↓
  Prioritization: [новые приоритеты...]

... цикл продолжается до завершения
```

## 3. ConversationalAgent & XMLAgent Pipelines

**Назначение:** Агенты с доступом к инструментам для выполнения действий. ConversationalAgent использует JSON формат, XMLAgent - XML теги.

**Файлы:**
- `packages/components/nodes/agents/ConversationalAgent/`
- `packages/components/nodes/agents/XMLAgent/`

### Общая схема ReAct Pattern

Оба агента используют паттерн **ReAct** (Reasoning + Acting):

```
┌──────────────────────────────────────────┐
│      ВХОДНЫЕ ДАННЫЕ                      │
├──────────────────────────────────────────┤
│ • User Input (запрос пользователя)       │
│ • Available Tools (список инструментов)  │
│ • Chat History (опционально)             │
└──────────────────────────────────────────┘
                    │
        ┌───────────▼────────────┐
        │    REACT LOOP          │
        │  (повторяется до       │
        │   финального ответа)   │
        └───────────┬────────────┘
                    │
        ┌───────────▼────────────────────────┐
        │  ШАГ 1: REASONING (Рассуждение)    │
        ├────────────────────────────────────┤
        │ Промт: System Prompt + User Input  │
        │ + Agent Scratchpad                 │
        │                                    │
        │ LLM анализирует:                   │
        │  - Что нужно сделать?              │
        │  - Какой инструмент использовать?  │
        │  - С какими параметрами?           │
        │                                    │
        │ Output (ConversationalAgent):      │
        │  {"action": "tool_name",           │
        │   "action_input": "params"}        │
        │                                    │
        │ Output (XMLAgent):                 │
        │  <tool>tool_name</tool>            │
        │  <tool_input>params</tool_input>   │
        └────────────┬───────────────────────┘
                     │
        ┌────────────▼───────────────────────┐
        │  ШАГ 2: ACTING (Действие)          │
        ├────────────────────────────────────┤
        │ Execution: Вызов инструмента       │
        │                                    │
        │ tool_result = execute_tool(        │
        │   name=action,                     │
        │   params=action_input              │
        │ )                                  │
        │                                    │
        │ Output: Результат работы tool      │
        └────────────┬───────────────────────┘
                     │
        ┌────────────▼───────────────────────┐
        │  ШАГ 3: OBSERVATION (Наблюдение)   │
        ├────────────────────────────────────┤
        │ Добавление в Agent Scratchpad:     │
        │                                    │
        │ scratchpad += f"""                 │
        │ Thought: {reasoning}               │
        │ Action: {action}                   │
        │ Action Input: {action_input}       │
        │ Observation: {tool_result}         │
        │ """                                │
        └────────────┬───────────────────────┘
                     │
        ┌────────────▼───────────────────────┐
        │  ПРОВЕРКА: Финальный ответ?        │
        ├────────────────────────────────────┤
        │ ConversationalAgent:               │
        │   Если нет "action" → Final Answer │
        │                                    │
        │ XMLAgent:                          │
        │   Если <final_answer> → Готово    │
        └────┬──────────────────┬────────────┘
             │ Нет              │ Да
             │                  ▼
             │         ┌──────────────────┐
             │         │ ФИНАЛЬНЫЙ ОТВЕТ  │
             │         └──────────────────┘
             │
             └──► Возврат к Шагу 1 (новая итерация с обновлённым scratchpad)
```

### XMLAgent: Детальный пример потока

```
User Input: "What is the weather in San Francisco?"

ИТЕРАЦИЯ 1:
  ├─ Промт:
  │  System: XML_AGENT_DEFAULT_SYSTEM_MESSAGE
  │  {tools} = "search: queries web for information"
  │  {input} = "What is the weather in San Francisco?"
  │  {agent_scratchpad} = "" (пусто на старте)
  │
  ├─ LLM Output:
  │  <tool>search</tool>
  │  <tool_input>weather San Francisco</tool_input>
  │
  ├─ Tool Execution:
  │  search("weather San Francisco")
  │  → "Current weather: 64°F, partly cloudy"
  │
  └─ Updated Scratchpad:
     <tool>search</tool>
     <tool_input>weather San Francisco</tool_input>
     <observation>Current weather: 64°F, partly cloudy</observation>

ИТЕРАЦИЯ 2:
  ├─ Промт:
  │  {agent_scratchpad} = (скретчпад из итерации 1)
  │
  ├─ LLM Output:
  │  <final_answer>
  │  The weather in San Francisco is 64°F and partly cloudy.
  │  </final_answer>
  │
  └─ ЗАВЕРШЕНИЕ: Возврат финального ответа
```

### Ключевые различия между агентами

| Аспект | ConversationalAgent | XMLAgent |
|--------|---------------------|----------|
| **Формат вывода** | JSON | XML теги |
| **Промт** | DEFAULT_PREFIX + инструкции | XML_AGENT_DEFAULT_SYSTEM_MESSAGE |
| **Парсинг** | Regex для JSON | XML парсер |
| **Лучше для** | GPT-3.5, GPT-4 | Claude, reasoning модели |
| **Структура** | `{"action": "...", "action_input": "..."}` | `<tool>...</tool><tool_input>...</tool_input>` |

## 4. MultiAgent Supervisor Pipeline

**Назначение:** Координация работы нескольких специализированных агентов через супервизора.

**Файл:** `packages/components/nodes/multiagents/Supervisor/`

### Схема работы

```
┌────────────────────────────────────────────────────────────┐
│               ВХОДНЫЕ ДАННЫЕ                               │
├────────────────────────────────────────────────────────────┤
│ • User Request                                             │
│ • Worker Agents = [Agent1, Agent2, ..., AgentN]           │
│ • Supervisor LLM                                           │
└────────────────────────────────────────────────────────────┘
                          │
            ┌─────────────▼──────────────┐
            │   SUPERVISOR ЦИКЛ          │
            └─────────────┬──────────────┘
                          │
┌─────────────────────────▼─────────────────────────────────┐

                            │
                  ┌─────────▼─────────┐

                  └────┬─────────┬────┘
                       │ Нет     │ Да
                       │         │
                       │         ▼
                       │  ┌────────────┐
                       │  │ ЗАВЕРШЕНИЕ │
                       │  └────────────┘
                       │
                       ▼

│  ШАГ 2: ВЫПОЛНЕНИЕ WORKER ЗАДАЧИ                         │
├──────────────────────────────────────────────────────────┤
│ Процесс:                                                  │
│   selected_worker.execute(task)                          │
│                                                           │
│ Output:                                                   │
│   worker_result = "Результат работы worker"              │

                       │
┌──────────────────────▼───────────────────────────────────┐
│  ШАГ 3: ОБНОВЛЕНИЕ КОНТЕКСТА                             │
├──────────────────────────────────────────────────────────┤
│ conversation_history.append({                            │
│   agent: selected_worker,                                │

```

## 5. Retriever Pipelines

Различные стратегии улучшения поиска информации.

### 5.1 MultiQuery Retriever

```
User Question → MULTI_QUERY_PROMPT → [Q1, Q2, Q3] →
  → Vector Search (для каждого Q) →
  → Объединение уникальных результатов →
  → Ranked Documents
```

**Преимущество:** Находит документы с разных "углов" зрения на вопрос.

### 5.2 HyDE Retriever

```
User Question → HYDE_PROMPT (для домена) →
  → Hypothetical Document →
  → Embedding (гипотетического док) →
  → Similarity Search →
  → Real Documents
```

**Преимущество:** Поиск по "идеальному" ответу вместо вопроса.

### 5.3 Condition Agent (AgentFlow)

```
User Input → CONDITION_AGENT_SYSTEM_PROMPT →
  {input, scenarios, instruction} →
  → LLM Analysis →
  → {"output": "selected_scenario"} →
  → Route to corresponding handler
```

**Преимущество:** Интеллектуальная маршрутизация запросов.
